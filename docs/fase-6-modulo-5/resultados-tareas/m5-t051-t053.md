# M5-T051–T053 — Editor de marca, restauración y recorrido conectado

Este documento conserva la evidencia del lote inicial. El editor vigente usa [el contrato de logo y acento](m5-t048-t050.md#contrato-vigente-de-logo-y-acento).

Verificación del 22 de noviembre de 2026 sobre backend `90c8307` y frontend `7380f07` más los cambios de este lote. Se reutiliza el [contrato HTTP de M5-T048–T050](m5-t048-t050.md). La implementación de producto vive en el repositorio `frontend-saas`. Su nota `docs/personalizacion-portal-m5-t051-t053.md` enumera los archivos y explica cómo participa cada uno.

## Flujo verificado

1. El Administrador abre **Personalizar portal** desde su cuenta. El frontend lee la publicación y los predeterminados usando la sesión existente. Las ediciones y la imagen seleccionada quedan en un borrador local.
2. La vista previa revisa el formato y las siete parejas de contraste del servidor. Un logo nuevo pasa primero las comprobaciones del navegador y se carga como provisional al guardar. El servidor lo sanea y publica su ID junto con los colores, condicionado a la versión original. Descartar conserva el estado anterior. Ante conflicto, el editor guía al Administrador para volver a consultar la publicación.
3. Restaurar muestra la apariencia predeterminada sin realizar una escritura. Cancelar recupera el borrador y aplicar manda solo la versión. El portal público lee la marca publicada del catálogo y solo carga el recurso bajo el slug del negocio que lo publicó.
4. El editor y la marca se revisaron por teclado y con el navegador en tamaño móvil y de escritorio. La demo reutiliza el diálogo con un estado ficticio en memoria.

## Pruebas y resultados

- **Pruebas primero.** Se escribió primero el recorrido de Playwright. El intento inicial quedó detenido en la conexión de MariaDB. Las pruebas unitarias nuevas de contraste y rutas fallaron antes de la implementación porque el módulo productivo todavía no existía.
- **Frontend unitario.** `npm test` · **306/306**. Los dos casos nuevos cubren formato, normalización, umbrales de contraste, foco interior y construcción de rutas de logo acotadas al slug.
- **Navegador con backend real.** `npm run test:browser -- tests/navegador/personalizacion.portal.spec.js` · **3/3**. El primer caso usa móvil en oscuro y comprueba foco, error de contraste, archivo con firma falsa, descarte sin escritura, publicación verificable, separación de negocios y restauración cancelada y confirmada. El segundo usa escritorio claro y dos sesiones para acreditar la recuperación tras un conflicto de versión. El tercero comprueba edición y descarte en la demo sin llamadas al API de marca.
- **Suite completa de navegador.** `npm run test:browser -- --trace on` · **35/36**. La traza de T124 mostró una recarga de Vite durante los cinco minutos de espera mientras se ajustaba el editor. La repetición aislada de T124 con archivos estables pasó **1/1** y verificó el aviso de vencimiento.
- **Integración de marca.** `npm run test:integration -- --runInBand --silent test/m5-t044-t047.integration-spec.ts` · **3/3**. Regresión de persistencia y saneado de logos.
- **HTTP de marca.** `npm run test:e2e -- --runInBand --silent test/m5-t048-t050.e2e-spec.ts` · **5/5**. Regresión de permisos, validación, escritura versionada, rollback y recurso público.
- **Unitarios del backend.** `npm test -- --runInBand --silent` · **682/683** en 103/104 suites. Se reprodujo el fallo previo de enlaces locales de `test/fase-5-t122-t124.spec.ts:23`, [registrado en el lote anterior](m5-t048-t050.md#unitarios).
- **Compilación y lint.** `npm run build` del frontend, TypeScript del backend con `--noEmit --incremental false` y `npm run lint` del backend completaron con código 0.

Las escrituras de navegador, integración y HTTP se ejecutaron en bases desechables de una instancia de MariaDB de prueba.
